# Veris 改版 UX 蓝图 v1（方向 A）

> 状态：2026-10-07。视觉与组件规格以 `design-system.md` 为准；本文定义每个页面要回答什么问题、按什么顺序摆放、有哪些状态、用什么文案。冲突裁决顺序见 `design-system.md` §0。
> 共同约束：
> - 不改现有 URL（分享链接、OAuth 回调、外部书签都不受影响）。
> - 只新增一个路由：`/runs/[id]/issues`。
> - 不删功能，只重组呈现。
> - 所有文案走 i18n（`messages/zh.json`、`en.json`），基础组件不调用 i18n。

每页按七项描述：①目标 ②信息层级 ③分区 ④线框 ⑤组件 ⑥状态 ⑦文案要点。

---

## 0. 全局外壳

- **顶栏（TopBar）：** Logo · 项目 / 规则库 / 知识库 / 设置 · （右侧）EN · 主题 · [新建分析]。
  - 当前一级页面的导航项加 600 字重和 `aria-current`。
  - 手机上主导航收进菜单按钮，抽屉里列同样四项。
- **页脚：** 一行 `Veris · v0.1.0 · 规则 rules_v10 · 协议 v2`，12px `--ink-3`。去掉营销式多栏页脚。
- **内容区：**
  - 最大宽度 1320px，页边距 16/24px；`main` 不再套第二层 `shell`。
  - 非诊断页的画布用 `--bg`，内容放在面板里。
  - 报告页的文档纸面用 `--surface`。
- **路由加载：** `loading.tsx` 统一用 `Skeleton`（无扫光），版式与目标页一致。
- **错误边界：** 标题「这个页面没能加载」+ 一句原因 + [重试]（primary）+ [返回项目]（secondary）。

## 1. 首页 `/`

1. **目标：** 打开就知道今天要处理什么。
2. **信息层级：** 待处理事项 → 项目列表 → 数据源就绪度。
3. **分区：** 待处理（最多 5 条）/ 项目（表格）/ 数据源一行状态。
4. **线框：**
```
[PageHeader] 工作台                                   [新建分析]
┌ 待处理 ─────────────────────────────────────────────────────┐
│ ■中 metadocu.com  12 条建议待确认                      去确认 → │
│ ■高 aichiplink.com 尚未诊断                          开始诊断 → │
└────────────────────────────────────────────────────────────┘
┌ 项目 ──────────────────────────────────────── 全部项目 → ┐
│ 域名 · 市场 · 最近诊断 · 待处理 · 下次复查 （表格，≤10 行）  │
└────────────────────────────────────────────────────────┘
数据源 2 / 4 已接入 · 未接入：Google 可见性检索、渲染抓取  去设置 →
```
5. **组件：** PageHeader、Panel、Table、SeverityMark、Notice（数据源一行）。
6. **状态：**
   - **无项目：** EmptyState「还没有项目」+「输入一个网址，先跑一次诊断」+ [新建分析]。
   - **待处理为空：** 一行「没有待处理事项」。
   - **数据源全部接入：** 不显示数据源那一行。
7. **文案：** 去掉 hero 口号。待处理条目的写法是「对象 + 数量 + 动作」。

**待处理的来源（只读现有数据，不新增字段）：**
- `reviewing` 状态且有 `draft` 建议的 run → 「n 条建议待确认」；
- 没有任何 run 的项目 → 「尚未诊断」；
- `next_retest_due_at` 已到期 → 「该复查了」；
- `failed` 状态的 run → 「诊断失败」。

## 2. 项目

### 2.1 项目列表 `/projects`

1. **目标：** 找到项目并进入。
2. **信息层级：** 搜索 → 表格。
3. **分区：** PageHeader（h1「项目」+ 搜索框 + [新建分析]）/ 表格。只保留一个 h1（现状页面上有两个 h1）。
4. **表格列：** 域名（mono，favicon 16px）· 市场 · 最近诊断（状态 + 时间）· 发现数 · 下次复查 · 行内操作（查看 / 发起回测）。
5. **状态：**
   - 无项目：同首页的空状态；
   - 搜索无结果：「没有找到包含"xxx"的项目」+ [清除搜索]。

### 2.2 项目详情 `/projects/[id]`

1. **目标：** 管理一个项目：看诊断历史、管数据接入、管品牌别名。
2. **信息层级：** 诊断历史（主体）→ 数据接入 → 品牌别名。
3. **线框：**
```
[PageHeader] 项目 / metadocu.com       h1 metadocu.com      [发起回测] [重新配置]
             全球英文（美国结果代理）
┌ 诊断历史 ───────────────────────────────────────────────┐
│ 时间 · 类型 · 状态 · 发现数 · 操作（查看 / 报告 / 以此回测） │
└──────────────────────────────────────────────────────┘
┌ 数据接入 ─────────────┐ ┌ 品牌别名 ──────────────────┐
│ Google Search Console │ │ 输入框 [添加]               │
│ 已连接 · 资源 xxx      │ │ 别名列表 / 空状态           │
└──────────────────────┘ └──────────────────────────┘
```
4. **组件：** PageHeader、Panel、Table、StatusText、Field、Button。
5. **状态：**
   - **GSC 卡片四种状态**各只显示一句话：未连接 / 连接中 / 已连接 / 授权失效。现状会把「正在读取…」和「已保存」同时显示，要修掉。
   - **诊断历史的时间：** 优先 `started_at`，回落到 `finished_at`；两者都没有显示「时间未记录」。
6. **文案：** 「以此回测」改为「以这次为基线回测」。

## 3. 诊断工作区（所有 `/runs/[id]/**` 共用）

用 `WorkspaceHeader` + `WorkspaceTabs` 取代现在的 `Shell` + `Stepper` + `SectionNav`。

```
项目 / metadocu.com / 基线诊断
metadocu.com                                   [主动作] [分享报告] [发起回测]
┌市场──────┬完成于────────┬检测协议┬规则版本─┬证据──┬数据源┐
│全球英文…  │2026-07-18 22:36│v2      │rules_v4 │78 条 │3 / 5 │
└──────────┴──────────────┴────────┴────────┴─────┴─────┘
✓ 采集证据 — ✓ 生成诊断 — ✓ 确认建议 15/15 — ● 执行 0/15 — 4–6 周后复查
概览  问题 15  建议 15  执行清单 0/15  报告            原始数据  站点结构 关键词 竞品 品牌事实
─────────────────────────────────────────────────────────────────────────
```

**进度（Lifecycle）与 `RunStatus` 的对应：**

| RunStatus | 采集证据 | 生成诊断 | 确认建议 | 执行 | 复查 |
|---|---|---|---|---|---|
| `draft` / `collecting` | 当前 | 未来 | 未来 | 未来 | 未来 |
| `collected` / `diagnosing` | ✓ | 当前 | 未来 | 未来 | 未来 |
| `reviewing` | ✓ | ✓ | 当前（已处理 / 总数） | 未来 | 未来 |
| `output` | ✓ | ✓ | ✓ | 当前（已执行 / 已接受数） | 未来；有到期日时显示日期 |
| `failed` | 失败那一步显示「失败」（`--sev-high`）+ 原因 | — | — | — | — |

- 历史兼容（沿用现 `Shell` 的规则）：`reviewing` 状态但建议已全部处理时，按 `output` 显示。

**主动作按状态变化（只有 1 个 primary）：**

| 状态 | 主动作 |
|---|---|
| 采集中 / 诊断中 | 无主动作，显示进度 |
| `reviewing` | 「确认建议（n 条待确认）」→ 建议页 |
| `output` | 「打开执行清单」 |
| `failed` | 「重新诊断」 |

### 3.1 概览 `/runs/[id]`

1. **目标：** 一屏看到「结论 + 先修什么」。
2. **信息层级：** 数据覆盖说明 → 结论句 → 检测结果表（4 行）→ 优先处理的 3 个问题 → AI 可见度 → Google AI 概览 → 引用情感（一行）。
3. **线框：** 见方向原型 `directions.html` 的「诊断概览」（A）。
4. **组件：** Notice、SectionHeader、ResultTable、EvidenceBadge、SeverityMark、Panel、Table + InlineBar、ShowMore、FilterChips（不用）。
5. **状态：**
   - **运行中**（`collecting` / `collected` / `diagnosing`）：概览主体换成「诊断进度」面板，列出 6 个阶段（发现页面 / 轻量抓取 / 聚类归组 / 深度检测 / AI 探针 / 生成诊断）。每个阶段显示 待开始 / 进行中 / 完成 / 失败 + 一句说明。不用流光动画，不用 BlurText / AnimatedList / CountUp。
   - **失败：** Notice（error）写明失败阶段和原因 + [重新诊断]。
   - **检测结果表里的某项未接入或失败：** 结果列写「未接入」或「采集失败」，说明列写原因，证据列留空。不用骨架屏，不显示开发者指令。
   - **AI 可见度没有探针数据：** EmptyState「本轮没有 AI 探针数据」+ 原因（未配置引擎 / 采集失败）+ [去设置]。
   - **引用域名超过 10 个：** ShowMore，默认显示前 10 个。
6. **文案：**
   - 结论句由已有数据拼出，例如「AI 目前不会主动推荐 {品牌}：{n} 个不提品牌名的提问里，提到你 {k} 次。」这是模板拼接，不是 LLM 生成的数字。
   - AI 口径说明写实际接入的引擎，例如「本轮只接入了 DeepSeek」。
7. **从概览移走的内容：**
   - 完整问题清单 → 「问题」视图；
   - 「诊断工作台」卡和第二个「下一步」卡 → 删除，由抬头的主动作代替；
   - SectionNav 的锚点药丸 → 删除，由视图导航代替。

### 3.2 问题 `/runs/[id]/issues`（新增路由）

1. **目标：** 看完全部问题，判断哪些可信、先修哪些。
2. **线框：**
```
问题 15        [全部 15] [高 1] [中 8] [提示 6]   [GEO] [SEO] [技术]
┌ ■高 页面存在 noindex 误用        P1 技术健康   实测   ▸ ┐
│   展开：描述 · 证据列表（证据 ID、采集时间、工具版本）· [查看原始证据]（抽屉） │
└───────────────────────────────────────────────────────┘
```
3. **组件：** FilterChips ×2（严重度、维度）、Table（可展开行）、SeverityMark、EvidenceBadge、Drawer（原始证据）。
4. **状态：** 没有问题时显示「本轮没有发现问题」；筛选后为空显示「没有符合筛选条件的问题」+ [清除筛选]。
5. **复用：** 改造现有 `FindingList` 的数据装配，页面的数据读取与概览页现有逻辑相同。

### 3.3 建议 `/runs/[id]/recommendations`

1. **目标：** 逐条确认建议，决定哪些进入执行清单。
2. **线框：** 见原型「优化建议」：
   - 筛选芯片：全部 / 待确认 / 已接受 / 已否决；
   - 按优先级分组；
   - 每条一行：严重度 · 标题 · 「针对：〈问题标题〉」· 影响 · 工作量 · 证据徽章 · 状态或操作；
   - 展开后显示：为什么 / 预期影响 / 风险 / 如何验证 / 证据 / 操作。
3. **状态：**
   - 待确认的行，行内直接显示「接受」「否决」；
   - 编辑在展开区内联完成：标题与说明的输入框 + [保存并接受] [取消]；
   - 操作进行中，按钮显示加载；
   - 操作失败，行内出现 Notice（error）写明原因，原状态保持不变。
4. **文案：**
   - 标题完全相同的建议必须靠「针对：〈问题标题〉」区分（现状有 3 条同名建议）。
   - 修复示例代码（`fixSnippet`）用 CodeBlock 显示，不混进正文句子。

### 3.4 执行清单 `/runs/[id]/output`（视图名改为「执行清单」，路由不变）

1. **目标：** 按顺序执行已接受的建议，生成执行提示词，标记完成。
2. **线框：**
   - 顶部进度：「已执行 k / N」+ 细进度条；
   - 列表（与建议页同一种行组件，只显示已接受和已编辑的建议）；
   - 展开区：执行资产（[生成执行提示词]；已生成的提示词用 CodeBlock + 复制）/ [标记已执行]（可填一句备注）；
   - 底部两块：回测说明、品牌事实闸门。
3. **状态：**
   - 提示词生成中；
   - 生成失败：沿用现有 404 / 409 / 422 / 502 分型文案，放在行内 Notice 里；
   - 全部执行完：Notice（success）「全部建议已执行，4–6 周后可以用同一协议回测」+ [安排回测]。

### 3.5 报告 `/runs/[id]/report`

- 工作台内的报告视图 = 分享报告的同一份文档（§5），外加顶部工具条：[导出 Markdown] [生成分享链接]（secondary）。
- 「打印 / PDF」保留为浏览器打印，打印样式用 `--surface` 纸面并隐藏工具条和外壳。

### 3.6 原始数据（站点结构 / 关键词 / 竞品 / 品牌事实）

- 统一结构：SectionHeader（视图名 + 一句口径说明）→ 汇总数字（ResultTable 或一行 Facts）→ 主表格（Table，长表用 ShowMore 或分页）。
- 关键词表：每行的「实测」徽章改为表头一次性说明（「全部来自 Search Console，实测」）；只有口径不同的行才单独标徽章。现状每行都有「实测」，是噪音。
- 竞品：候选竞品用表格行 + 行内「确认 / 驳回」，不用 2 列卡片。
- 品牌事实：表单用 Field；状态用 StatusText（已核验 / 草稿 / 已停用）。

## 4. 新建分析 `/new`

1. **目标：** 用最少的输入开始一次诊断。
2. **结构：** 页面顶部二选一（FilterChips 样式的分段切换），不再上下堆两个表单，也不再出现两个步骤条：
   - **诊断一个网站**（默认）：网址 → 产品 / 服务品类（英文）→ 目标市场 → 关键词（可选）→ 竞品（可选）；右侧一栏放「预计耗时 / 成本 / 调用次数」（预估，非实测）。
   - **从一个问题开始**：一个多行输入框「你想解决什么问题」+ 域名（可选）→ [生成诊断路线]，即现有的 GoalAnalysisLauncher 能力。
3. **状态：**
   - 网址格式错误：实时提示，文案走 i18n；现状硬编码了「✓ 格式正确 / ✗ 格式无效」。
   - 提交中：主按钮显示加载。
   - 未连接 GSC：一行 Notice（info）「建议连接 Search Console，补充点击和排名数据」+ [连接]。
4. **删除：** 黑色「INTELLIGENT INTAKE」面板、版本小芯片条、引擎 emoji 芯片（改为纯文字的引擎名单）、三步迷你步骤条（改为分组小标题）。

## 5. 分享报告 `/share/[token]`（客户看到的页面，固定浅色，手机优先）

1. **目标：** 不懂 SEO 的站主读完能回答三个问题：「我现在怎么样？先做哪 3 件事？这些结论靠不靠得住？」
2. **信息层级：** 抬头（Facts）→ 规则版本说明（如有）→ ① 结论（3 条，按严重度排序）→ ② 先做这 3 件事 → ③ 关键数据（ResultTable + 5 维度条）→ ④ 证据等级怎么读 → ⑤ 下一次复查 → 详细章节（优先级矩阵、行动路线、五支柱明细、GEO 补充、关键词、竞品、方法与范围、回测，按现有 ReportView 的 9 章保留，默认折叠为 Disclosure）→ 页脚（报告编号）。
3. **线框：** 见原型「分享报告」（A），桌面 860px 纸面；手机满宽，左右 20px 边距。
4. **状态：**
   - 链接过期或不存在：一句「这个报告链接已失效」+ 联系方式说明（纯文本，不用 `mailto:` 按钮）；
   - 数据不全的章节：写明「本次诊断没有采集 X，所以这一节为空」。
5. **文案：** 每条结论都是一句白话 + 证据徽章。报告编号格式 `R-<run id 前 8 位>`。
6. **删除：** BlurText 标题动画；CountUp 健康分；裸 HTML 片段混进正文（改为 CodeBlock）。

## 6. 其它页面（同一套外壳和组件，不再各自成风格）

- **规则库 `/rules`：**
  - PageHeader（h1 + 一句说明）+ 视图标签（待审提案 / 手动建提案 / 版本记录）+ Table；
  - 去掉渐变页头和脉动图标；
  - 「批准」用 primary，「驳回」用 secondary，「发版」用 primary。
- **设置 `/settings`：**
  - PageHeader + 「共享服务」：每个数据源一个 Panel，标题 + 状态（未接入 / 已接入 / 读取环境变量）+ 字段；
  - 去掉 emoji 小标题（🎯🚀📋）和脉动图标；
  - 「配置指南」用 Disclosure。
- **知识库 `/knowledge`：**
  - 去掉方格纸 hero、装饰圆环、英文大写眉标、黑色按钮；
  - PageHeader + 视图标签（来源 / 论点审核 / 正式知识 / 工作流闸门，各带计数）+ Table / Panel；
  - 来源状态用 StatusText（空闲 / 失败），失败行内写原因。
- **分析会话 `/sessions/[id]`：**
  - PageHeader（h1 = 问题原文，下方 Facts：场景 / 状态 / 知识版本 / 工作流版本 / 规则版本）；
  - 执行路线用有序列表（步骤是真实顺序，可以编号）；
  - 引用知识用 Table。
- **404：** 「页面不存在」+「链接可能已失效，或项目已被删除」+ [返回项目]（primary）。修复现状的幽灵类 `acc`。
- **错误页：** 见 §0。

## 7. 营销站 `marketing/`（英文，手机优先）

- **共同：**
  - 使用同一套 token，从 `app/tokens.css` 同步，由测试保证两份一致。
  - 字体与 Logo 和应用相同。
  - 去掉 Apple 蓝。
- **首页：**
  - 左对齐首屏：h1 38px + 一句说明 + [Request early access] + 「How we grade evidence」链接；
  - 右侧放一段真实诊断摘录（与原型一致，标明来自真实运行）；
  - 下面依次是「What you get」（4 项，两列文字，不做卡片）和证据阶梯表。
- **方法论：** 正文最大宽度 65ch，证据阶梯用表格（L0–L4），「What Veris is not」用列表。
- **博客：**
  - 列表页：没有文章时显示「No posts yet」+ 一句说明，不显示空白页；
  - 文章页：用 `ui-prose` 排版。
