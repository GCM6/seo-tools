# Veris 全站 UI 审查与改版方向（2026-10-07）

> 范围：工作台 `app/[locale]/**`、客户分享报告 `app/share/**`、营销站 `marketing/`（用户 10-07 确认三者一起改）。
> 方向原型：`docs/design/2026-10-07-redesign/directions.html`（已发布为私有 Artifact：https://claude.ai/artifact/RBfnN43bLVUcCEaqoUtSUQ ）。
> 证据标签：**observed** = 本轮亲自截图、读代码或跑脚本得到；**derived** = 由观测数据推出；**reported** = 来自文档或记忆，未在本轮核实。

## 1. 结论

现在的 UI 不协调，根子在于**没有一套被遵守的设计系统**。主题变量是从另一个项目「炼图术 Studio」整段搬来的（Apple 蓝 + 「AI 紫」体系），之后每个功能都在一份只增不减的 5757 行 `globals.css` 里各自造组件。结果是：

- 同一站点并存 **5 种以上视觉风格**；
- 颜色同时承担品牌、证据等级、优先级三种含义，**语义互相打架**；
- 首页和诊断页集中了渐变、发光、无限动画、大写英文标签等**典型「AI 味」元素**。

改版要做两件事：

1. 定一套只有少量组件、语义清楚的设计系统；
2. 把诊断页从「向导 + 长滚动」改成「工作区 + 结论先行」。

三个视觉方向已做成可切换原型，等你选。

## 3. 问题清单（按用户能看到的影响排序）

### 3.1 视觉风格分裂成 5 种以上（observed）

| 风格 | 出现在哪 | 特征 |
|---|---|---|
| 青色 + Apple 灰 | 首页、项目、诊断页主体 | `.card` 圆角 12px |
| 「粗野主义 / 终端」 | 新建分析的「INTELLIGENT INTAKE」黑色面板、知识脑、Session | 硬偏移阴影、方格纸背景、8–10px 等宽大写英文标签 |
| Tailwind SaaS 模板 | 规则库、设置 | 渐变页头、脉动图标、emoji |
| 渐变装饰卡 | 诊断概览 | 青色渐变 CTA、暖色渐变结论卡、淡紫品牌卡、青色渐变 AIO 卡 |
| 几乎无样式 | 404、品牌事实、关键词表 | — |

- 内容最大宽度有 5 种：1120 / 1180 / 980 / 960 / 896。
- 项目页出现 `shell` 嵌套 `shell`，内外边距叠加。

### 3.2 颜色语义冲突（observed）。对一个靠「证据分级」立身的产品，这是最严重的问题

**一种颜色身兼多职：**

| 颜色 | 同时代表 |
|---|---|
| 青色 | 品牌主色、证据「实测」、优先级「重点投入」 |
| 橙色 | 证据「推断」、严重度「中」、优先级「顺手补齐」 |
| 黑色 | 优先级「优先处理」、步骤条「当前步」 |

**「达标」色被用在了问题上：** 严重度 `ok` 的问题条目显示为绿色圆点（绿 = 达标），但这些条目写的是「缺权威 sameAs」「无 Knowledge Panel」「E-E-A-T 代理信号缺失」这类缺口。i18n 里 `ok` 一处译「提示」，另一处译「已具备：已核验达标项」。

**状态色有 4 套：** 证据色、iOS 系统色、知识脑字面量色、Tailwind 原色。同一个「已连接」在不同页面分别是三种绿或青。iOS 绿、橙作文字时对比度只有 2.0:1；`state-unknown` 芯片只有 1.6:1（derived，按 WCAG 公式计算）。

**旧体系残留：**
- 全站文字选区是 Apple 蓝 `#005bb5`；
- `--ds-border-primary` 仍是 Apple 蓝，但没有任何地方引用；
- 「AI 紫」`#6366f1` 散落在发版按钮、设置徽章、首页极光动画里。

### 3.3「AI 味」集中区（observed）

**首页 hero 一屏叠了 6 个无限循环动画：**
- 旋转流光边框；
- 渐变文字闪光；
- CTA 呼吸光晕 + 横向扫光；
- 50px 模糊「极光」球（含靛紫）；
- 「AI 呼吸脉冲点」。

另外还有网格背景加径向遮罩。文案「用事实与实测，穿透 SEO 与 GEO 迷雾」是口号式写法，和「不是 AI SEO magic 工具」的产品定位相冲突（定位见 CLAUDE.md，reported）。

**`components/fx/` 的动效组件：**
- BlurText（模糊入场）：用在运行进度和报告页；
- CountUp（数字滚动）：用在运行进度和健康分；
- AnimatedList（列表飞入）：用在运行进度。

**标签与符号：**
- TSX 里硬编码了至少 23 处全大写英文标签，例如「INTELLIGENT INTAKE / W0」「VERIS / KNOWLEDGE OPERATIONS」「ANALYSIS SESSION /」，都没有走 i18n；
- TSX 里有 8 个 emoji：引擎芯片 🟢🔵✨🐋🔍，设置页 🎯🚀📋。

**装饰泛滥（不只首页）：** 彩色阴影 20 处，装饰圆环 4 处，linear-gradient 24 行。

**卡片样式：** 卡片带彩色左边条，正是当前常见的模板化做法（参见 artifact-design 的「AI 生成设计」清单，reported）。

### 3.4 信息架构与交互（observed）

**首页是落地页，不是工作台。** 有营销 hero 和营销式页脚（导航 + 方法论），而这是单人内部工具。

**新建分析页叠了两套表单和两个步骤条：** 上面是「智能入口」自由文本表单，下面是三步向导，页面顶部还有全局四步条。

**四步步骤条（新建 / 诊断 / 建议 / 输出）兼做导航，** 出现在所有诊断子页。手机上被横向截断，暗色下当前步变成白块。

**诊断概览 11,103px 高：**
- AI 概览引用域名逐行渲染 138 个，每行一个独立边框盒；
- 查询列表 21 行，也是每行一个盒子；
- 真正要处理的「问题清单」排在页面最底部；
- 页面上有两个互相矛盾的「下一步」：一个写「查看输出」，一个写「先看问题与证据，再确认建议」。

**建议页每张卡约 360px 高：**
- 「预期影响」这种整句文字被塞进三个窄格；
- 3 条建议标题完全相同（「根据证据优化该内容页……」），列表里分不出来；
- 新版要在行内显示「针对：〈问题标题〉」。

**术语漂移：** 同一个优先级在建议页叫「优先处理 / 重点投入 / 顺手补齐 / 暂缓处理」，在报告矩阵里叫「速赢 / 战略 / 填充 / 低优先」。

### 3.5 状态处理（observed）

- **未接入的数据源用骨架屏表示。** 看起来像在永远加载；同一张卡里还直接显示开发者指令「在 .env 配置 GOOGLE_CSE_API_KEY…」。
- **AI 回答显示原始 Markdown**（带 `**` 星号）。
- **报告里有裸 HTML 代码片段。** `<meta name="robots" …>` 混在正文句子里，没有排成代码。
- **诊断历史表的时间显示不对：** 一行是裸 ISO 时间 `2026-07-13T07:05:02.556Z`，其余四行显示「—」。原因是只读了 `started_at`，没有回落到 `finished_at`（DB 里 4 条 run 的 `started_at` 为 null）。
- **AI 探针的口径说明与实际接入不符：** 说明写「ChatGPT / Perplexity / Gemini / DeepSeek」，实际本轮只接入了 DeepSeek 1 个引擎。

### 3.6 暗色与对比度（observed + derived）

- **暗色下至少 6 处文字对比度约 1:1。** 原因是引用了未定义的 `--ds-fg`，以及半透明白底芯片。
- **暗色下实心主按钮只有 2.91:1。** 主色变亮了，按钮文字仍是白色。
- **黑色面板在暗色下整块反成白色，** 例如新建分析页的智能入口。
- **暗色加载时有 hydration 报错：** 主题脚本在 hydration 前给 `<html>` 加了 `dark` 类，React 报 attribute mismatch（observed，浏览器控制台）。
- **浅色下的低对比文字：** `--ds-ghost` 作文字只有 2.21:1，`--ds-muted` 3.6:1。

### 3.7 组件失控（observed）

| 组件 | 现有写法数 |
|---|---|
| 实心主按钮 | 17+ |
| 卡片 / 容器 | 30+ |
| 徽章 / 标签 | 约 30 |
| 空状态 | 约 12 |
| 页头 | 12+ |

- **幽灵类 `acc` 在 CSS 里不存在。** 404 页、错误页、「保存编辑」、回测到期横幅的主按钮因此退化成透明按钮。
- **`RetestBanner` 整条横幅没有任何样式。**
- **同一个「发起回测」按钮在 4 个地方有 4 种外观。**

### 3.8 字体（observed）

- **字号：** CSS 里有 37 种字号，93% 没有走 `--text-*` 阶梯；TSX 里的 177 处字号全部绕过阶梯；小于 11px 的声明有 51 条，最小 8px。
- **字重与字距：** 字重 7 种（含 650），字距 20 种取值。
- **字体：** 当前用 Geist。GEO 竞品 Peec 的官网也用 Geist（observed）；Inter 是参照站里最常见的默认字体（6/10，observed）。

### 3.9 营销站与应用品牌不一致（observed）

- **品牌色与 Logo 不一致：** 营销站主色是 Apple 蓝 `#0071e3`，应用是青色 `#0B6E74`；营销站只有文字 Logo，应用是三角标志加双色字标。营销站 CSS 注释写着「取自根应用，保持品牌一致」，但值不同。
- **版式是通用模板：** 居中 hero、2×2 功能卡、灰色色带、居中 CTA。
- **博客为空：** `content/blog` 只有 `.gitkeep`。

### 3.10 工程根因（observed）

**`globals.css`：**
- 5757 行、571 个类；
- 两段「UI/UX 修复补充」追加区约 930 行；
- 死类约 48 个；
- 重复定义的选择器 28 个；
- `!important` 48 处；
- 未定义变量引用 8 处。

**三种写法混用：** Tailwind 类 1632 个、全局类 1102 个、内联 style 对象 128 个。

**shadow token 没有注册进 `@theme`，** 所以 `shadow-card` 等 11 处类名实际不生成任何样式。

## 4. 参照站实测要点（observed，详见子代理报告）

| 维度 | 实测结果 |
|---|---|
| 浅色主文字 | 都不用纯黑（8/9）：如 Stripe `#061b31`、Vercel `#171717`、Primer `#1f2328`、Linear `#282a30` |
| 浅色边框 | 都是极浅灰，范围 `#d1d2d5`–`#f4f5f7`（9/9） |
| 圆角 | 最高频值是 6px 的有 6 站：Linear、Vercel、Plausible、Primer、Stripe、Semrush；非圆形最高频值在 4–8px 的有 9/10 站 |
| 正文字号 | 14–16px（8/10） |
| 行动色 | 克制组（Linear、Stripe、Plausible）在语义 token 层只定义一个行动色相；SEO/GEO 竞品（Ahrefs、Semrush、Profound）饱和色相多* |
| 渐变 | Plausible 0、Primer 0、Linear 抽样仅 8 处；营销站普遍较多：Vercel 109、Profound 81、Stripe 70 |

GEO 竞品里「AI 味」最重的是 Profound：仅暗色，黄、蓝、紫多色并用，81 处视觉渐变，26 处 backdrop-filter。Veris 的差异化应该落在**克制**上。

## 5. 改版原则（三个方向共用）

1. **颜色只表达严重度和回答质量。** 证据等级用形状编码：实心 = 实测，空心 = 推断，虚线 = 假设。优先级用文字和排序表达。不再让同一颜色承担两种含义。
2. **每种用途只保留一个组件：** 一种面板、一套按钮（主 / 次 / 安静）、一种严重度标记、一种证据标签、一种表格、一种空状态、一种页头。
3. **结论先行。** 每页第一屏回答一个问题；超过 10 行的列表默认折叠。
4. **诊断页是工作区，不是向导。** 抬头写清协议、规则、证据数和进度；视图导航分为概览 / 问题 / 建议 / 执行清单 / 报告 + 原始数据。
5. **工具外壳要安静。** 没有 hero，没有营销页脚。
6. **状态写实话。** 写明「未接入 / 未测量 / 失败」，并给一个动作；不用骨架屏冒充数据。
7. **动效只为功能服务。** 120–200ms 的展开或切换；遵守 `prefers-reduced-motion`。

**Never 清单（否决级，不随审美讨论改变）：**
- 渐变、发光、毛玻璃、模糊入场、数字滚动、列表飞入；
- 网格或点阵装饰背景、装饰圆弧、大色块横幅；
- 英文大写等宽小标签、emoji、星星类「智能」图标；
- 卡片彩色左边条；同一页出现两种以上面板样式；
- 用颜色表示优先级；一个颜色同时代表两件事；
- 用骨架屏冒充「没有数据」；
- 超过 10 行的列表默认全部展开。

## 6. 三个视觉方向

原型里用同一份真实数据，可以切换页面（诊断概览 / 优化建议 / 分享报告 / 营销首页）、方向和明暗主题。108 组前景 / 背景色对已用脚本按 WCAG 公式实算，全部达到 AA（正文 ≥ 4.5:1，图形 ≥ 3:1）。

| 方向 | 气质 | 适合 | 代价 |
|---|---|---|---|
| **A 报告**（检测报告式） | 方正、表格化，抬头写协议和规则版本；IBM Plex Sans + 思源黑体；墨水蓝；圆角 2px | 对外交付、需要显得严谨可信 | 工作台偏正式；2px 圆角比主流工具（6px）更硬 |
| **B 工具**（专业软件式） | 左侧视图导航，紧凑方块和表格；系统字体；保留品牌青；圆角 6px | 自己每天操作、扫读大量数据 | 分享报告更像软件截图；辨识度最低 |
| **C 极简**（体检报告式） | 大字、大留白、黑白为主，数字配白话；Source Sans 3 + 思源黑体；黑色按钮 | 给不懂 SEO 的站主看 | 工作台一屏信息最少；品牌色存在感最弱 |

**推荐 A。** 产品卖的是「可核验」，检测报告的版式本身就在表达这一点：抬头写协议、规则版本和证据数，每个结果旁边是证据等级（derived）。A 和所有实测竞品都拉开了距离：不用 Inter / Geist，不用渐变，不用多色（observed）。如果你更看重日常操作效率选 B；主要给站主看选 C。三个方向可以在同一套 token 上配「紧凑 / 宽松」两档密度，所以不必为工作台和报告各选一个方向。

## 7. 默认决策（按「默认值推进」，你可以逐条改）

1. **暗色模式：** 保留，全部由 token 驱动；分享报告固定浅色（客户转发、打印都友好）。
2. **手机端：** 分享报告和营销站按手机优先设计；工作台桌面优先，手机上可用、不横向滚动。
3. **品牌：** 保留 Veris 名称和三角标志的外形，改为单色。品牌色随方向：B 保留青色，A 换墨水蓝，C 用黑色。
4. **字体：** 不再用 Geist 和 Inter，具体字体随方向。
5. **不改 URL、不删功能，只重组呈现。** 分享链接、OAuth 回调不受影响。
6. **动效：** 移除 `components/fx/` 三个组件和首页 6 个无限动画。
7. **首页：** 改为工作台首页，内容是待处理事项和项目列表，不再是营销 hero。
8. **新建分析：** 两个入口（按问题分析 / 诊断网站）改成同一页二选一，不再上下叠两个表单和两个步骤条。
9. **应用页脚：** 只保留一行版本信息。
10. **营销站：** 保持英文，套用同一套 token，替换 Apple 蓝；hero 旁边放一段真实诊断结果摘录，替换 4 张功能卡。
11. **文案：** 去掉英文大写标签和 emoji；口号式标题改为直述；术语统一，优先级只保留一套叫法。
12. **实施顺序：** 先做 token 和基础组件，再逐页替换，最后删除旧 CSS。每一层都跑全量测试，并逐页截图对比。

## 8. 后续阶段（选定方向后）

1. **规范固化：** 写 `design-system.md`。内容包括 token 表、组件规格、交互状态矩阵、断点表，以及可以重跑的对比度脚本。
2. **实施计划：** 按依赖分波。第一波是 token + 基础组件 + 外壳；第二波是诊断工作区（概览 / 问题 / 建议 / 执行清单 / 报告）；第三波是其余页面和营销站；第四波删除旧 CSS 和死代码。
3. **验收：** 每波跑全量 vitest + tsc + lint + build，桌面、手机、暗色三档逐页截图并对比，用元素级断言检查溢出和对比度。
4. **封版：** 列交付物清单和 md5、冲突裁决顺序、遗留开口，并提交 git 基线。

## 9. 风险与没有核实的部分

**原型的覆盖范围：**
- 只做了 4 个页面；问题、执行清单、原始数据等视图沿用同一套组件，但还没有画；
- 原型里有 2 条建议被手动改成「待确认」，用来演示交互，真实数据中 15 条都已接受。

**代码审计中只做了推算、没在浏览器里实测的条目：**
- 第 3.6 节的暗色对比度，按纯色底计算；
- 第 3.7 节的按钮外观。

**参照站实测的局限：**
