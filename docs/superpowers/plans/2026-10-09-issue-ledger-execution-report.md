## 三、相对计划的关键裁定

审查中发现计划自带代码有缺陷时，按规格裁定修正，主要有：

1. **对账语义（Task 8）**：复发只认此前「已修复 / 自行消失」的问题（体检进行中标记执行，不会被清空执行记录）；严重度 / 受影响数只在同一规则版本、同一协议下比较，口径变了只打标记、不撤销人的「暂不处理」；同一次体检对账两次时，已查过的问题保持第一次结果；「没查」在变化记录里不写成「查过没查出」。
2. **空协议指纹 = 无法确认一致**：历史问题的协议指纹为空，抽样类（AI 引用等）问题在第一次真实体检中未命中时关闭为「已关闭（检测口径已变或无法确认一致）」，不判已修复。
3. **回填的规则版本 = 未知（终审 C1）**：历史观测跑在 rules_v1–v10 下，回填一律记规则版本 0。第一次真实体检未命中的历史问题关闭为「不可比 · 规则已更新或历史版本未知」，而不是「自行消失」。终审在真实数据副本上复现过修复前的误判（C06、C09、T03（高）、T07、TA01 五个已纳入问题会被说成自行消失）。
4. **人工动作状态闸门（Task 12）**：撤销执行只在「已执行，待复查」时允许；已修复的问题不能再执行、暂不处理或标误报；旧界面桥接遇到这类拒绝时跳过，不报错。
5. **读抓取数据的规则声明依赖抓取（终审 I1）**：T01、C05a/b/c、C06、C07、E01、IPF01–03 在抓取没采到时记「没查」，不再把没看过的页面判成「没了」。
6. **同协议沿用种子词（终审 I2）**：避免关键词样本变化被误判成「已修复 / 部分改善」。
7. **竞品确认后的局部对账（Task 11）**：只补主诊断当时「没查成」的规则；已经查过的规则保持原结果（确认竞品会改变协议，重测属于下一次体检）。
8. **复查提醒**：改为「仍在待复查的问题里最早一次执行 + 28 天」，撤销执行或复查后重算；输出页文案同步改正。
9. **回填事件顺序**：回填写入的事件 ID 按写入顺序递增，问题清单里同一时刻的「决定」链不会倒序。
10. **验收口径修正**：计划里一条回填核对 SQL 的期望值写错（按实现，未查出的旧体检也会写「未复查」记录），改为按「查出」计数核对。

## 四、已知限制与遗留（按影响排序）

- **范围级复查（规格 §9-6）**：按页 / 按模板的规则，在本次只复查到部分页面时（单页深检失败被跳过、模板代表页每次可能不同、抓取 partial 也算可用），没复查到的范围仍可能被判「没了」。在 §8.3 第 2 轮验收前需要处理或明确告知。
- **C05d** 也读深检页数据但未声明依赖抓取（只在配置托管渲染且抓取不可用时触发，V0 界面走不到）。
- **并发覆盖**：`saveIssueChanges` 整行覆盖；对账读写之间若有人工动作会被覆盖（毫秒级窗口，V0 单操作者）。
- **关键词缺口重复行**：主诊断与竞品再评估都会写同一次体检的缺口，读取方按关键词合并，界面不受影响。
- **问题清单文档**：只有决定与执行时间，看不出决定的具体类型（暂不处理 / 误报都显示为「已排除」）；历史发现没有受影响数（显示「受影响数未记录」）。
- **旧界面过渡期**：旧报告的回测章节对新体检不再有数据；`recommendations.outcome` 不再写入（规则效果统计属「待定」范围）。
- 其余次要项（测试覆盖、注释、提交信息格式、索引、提取器细节等）共约 50 条，已在终审中逐条分级为「以后处理」，子项目 2 动到相关代码时顺手处理。
